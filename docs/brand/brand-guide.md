## 13. Illustration system

Specified here, and **produced in Phase 3**. Nothing below is drawn yet.

### 13.1 Confirmed direction

Exploded-view engineering illustration, isometric layers, precise callouts, title blocks, device frames, a
commit-graph spine, and a stylised character. Artistic and graphic, not a generic programmer aesthetic, with a
premium engineered-product feeling.

### 13.2 On 3D (OWNER-DIRECTED)

- The intent is to avoid **decorative or photorealistic** 3D. Flat and isometric vector depth is the default.
- Useful 3D is **not banned categorically.** A future engineering visualisation that genuinely benefits from
  real depth (for example a rotatable exploded device) can be proposed.
- **PROPOSED approval gate (AG-8):** a proposal states the benefit over 2D, the file and runtime budget, and
  the reduced-motion and accessible fallback, and needs the owner's explicit approval.
- No 3D or WebGL work is planned in any current phase.

### 13.3 Default style (PROPOSED)

Flat fills from the approved palette, at most four palette colours per illustration plus `ink` and `paper`.
Every shape has an `ink` outline. Depth comes from stacking and offset shadows. The default excludes
gradients, blur and photography.

### 13.4 Avoid (CONFIRMED)

Matrix rain, fake terminal UI, floating technology logos, a dark hacker aesthetic, code walls, and generic
programmer tropes. A code snippet, if ever used, is at most 6 real, sanitised lines (PROPOSED).

### 13.5 Composition rules (PROPOSED)

- One focal point per composition. At most 6 callouts per viewport.
- Callouts never cover the character's face.
- **Labels are HTML, never baked into SVG.**
- Layer identity is never colour alone: number, label and hatch pattern too (in force with D3).
- Three tiers per composition. **T1:** headline type and the hero object. **T2:** character and callouts.
  **T3:** title block, hairlines and grid. Alignments follow the isometric axes. Composition is asymmetric.

### 13.6 The exploded stack (PROPOSED details, CONFIRMED layer IDs)

One file, where **assembled and exploded are the same art at different offsets.** The six layer IDs are
frozen (D10).

| Plane  | Layer ID     | Contents                                                      |
| ------ | ------------ | ------------------------------------------------------------- |
| 1      | `interface`  | Generic UI blocks (not a fake app)                            |
| 2      | `components` | Six wireframe tiles (button, card, input, list, chip, toggle) |
| 3      | `state`      | Nodes and arrows                                              |
| 4      | `native`     | Module blocks with connectors                                 |
| 5      | `delivery`   | Base plate                                                    |
| Blocks | `leadership` | Three detachable cuboids, the hand-off object                 |

Plane geometry: a 720-unit isometric rhombus, 16 units thick. The explode gap runs from 0 to 168 units, with
vertical dashed connectors and tick marks. Each plane carries its layer ID, callout anchor points and an
explode offset.

### 13.7 Device frames (PROPOSED)

Generic, with **no manufacturer likeness or branding.** The screen is a real cut-out (even-odd path, no mask),
and the image or video sits behind the frame.

### 13.8 Callouts, labels, title blocks (PROPOSED)

- **Callout kit:** leader lines (straight, or elbow at 45° or 90°), dot and open-arrow end markers, numbered
  pins (24 px circle), dimension ticks (8 px), registration mark (16 px), crop marks (12 px). All `ink`.
- **Title block:** a four-cell strip at the base of each section (`SHEET n/N · SECTION · REV · SCALE`). Fields
  are HTML, and values derive from data.

### 13.9 Backgrounds and decoration (PROPOSED)

- **Isometric grid:** an SVG pattern (30° lines, 64-unit pitch), 10% opacity or less, never animated.
- **Decorative bricks** (small cuboids as bullets and dividers): P2, at most 3 per viewport. Paper-grain
  texture: P2, only if it costs under 5 KB.

### 13.10 Reusable primitives (PROPOSED)

`iso-plane`, `iso-cuboid`, `leader`, `pin`, `dimension`, `regmark`, `titleblock`, `hatch-*` (six), `chip`,
`commit-node`, `spine-segment`, `frame-phone`. Each is a static SVG source when produced.
